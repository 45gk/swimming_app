# План настройки Mac для разработки

**Цель:** подготовить базовое окружение для разработки на Mac с Apple Silicon и устанавливать только те языки и библиотеки, которые понадобятся для реальных проектов.

## Текущее состояние

- Mac на Apple Silicon, macOS 27.0.1.
- Xcode 27.1 установлен.
- Visual Studio Code установлен; команда `code` доступна в Terminal через `~/.local/bin`.
- Node.js 24 и npm установлены.
- `uv` установлен; системный Python — 3.9.6.
- Git установлен, имя и email уже настроены.
- Homebrew 7.0.10 установлен и доступен в login shell.
- `fd`, `fzf`, `bat`, `tree` и `direnv` установлены через Homebrew.
- Интеграции `fzf` и `direnv` добавлены в `~/.zshrc` и проверены в интерактивном `zsh`.
- Docker Desktop установлен; Docker CLI и Compose доступны.
- GitHub CLI 2.102.0 и `ripgrep` 15.2.0 установлены через Homebrew.
- Рабочая папка пуста, поэтому стек проекта ещё не определён.

## Этапы

### 1. Homebrew — готово

- Homebrew добавлен в `PATH` через `~/.zprofile`.
- `brew --version` работает в login shell.
- `brew doctor` сообщает о неуправляемых Homebrew Node.js-заголовках в `/usr/local/include/node`; это предупреждение, не блокирующее работу.

### 2. Docker Desktop — готово

- Docker Desktop запущен; активный контекст — `desktop-linux`.
- Docker Engine отвечает как версия 29.9.1.
- `docker compose version` сообщает v5.6.0.
- Одноразовый `hello-world` контейнер успешно запущен и автоматически удалён (`--rm`).

### 3. CLI-инструменты — готовы

- `gh` — работа с GitHub из Terminal.
- `rg` и `fd` — быстрый поиск по тексту и файлам.
- `fzf` — интерактивный поиск; горячие клавиши `Ctrl+R` (история команд) и `Ctrl+T` (файлы).
- `bat` и `tree` — просмотр файлов с подсветкой и дерева каталогов.
- `direnv` интегрирован с `zsh` для загрузки переменных окружения проекта из `.envrc`.
- При необходимости войти в GitHub через `gh auth login`.

### 4. Подготовить редактор и Python для проекта

- Команда `code` добавлена в `~/.local/bin` и проверена в login shell.
- Не менять системный Python. Для конкретного Python-проекта создать локальную среду с `uv` и зафиксировать зависимости в проекте.
- Выбрать версии Python, Node.js и других языков по требованиям проекта; не устанавливать дополнительные runtime заранее.

### 5. Проверить готовность на первом проекте

- Открыть папку проекта в VS Code.
- Настроить `.gitignore`, форматтер/линтер и тестовые команды по используемому стеку.
- Если проект использует контейнеры, добавить `Dockerfile` и/или `compose.yaml` под его конкретные сервисы.
- Проверить сборку, тесты и контейнерный запуск на самом проекте.

## Критерии готовности

- `brew --version` работает; `brew doctor` выдаёт только предупреждение о заголовках Node.js в `/usr/local/include/node`.
- Docker Desktop запускается; `docker run --rm hello-world` завершается успешно.
- `gh --version` и `rg --version` доступны из Terminal.
- `fd`, `fzf`, `bat`, `tree` и `direnv` доступны из Terminal.
- Для первого проекта версии runtime и зависимости заданы в его конфигурации, а не установлены глобально без необходимости.
